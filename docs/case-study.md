# Anonymized case study

## Situation

一个长篇中文科幻项目在签约前需要重做前三章。原稿的主要问题不是错别字，而是：术语密度过高、叙述者反复替人物解释、工作元数据容易混入发布稿，以及三章之间的数字和信息边界需要反复核对。

## Workflow

1. 将原稿放在私有目录，不进入公开仓库。
2. 用人工规则固定章节顺序、硬数据和信息边界。
3. 先保留工作稿元数据，完成逐章修改。
4. 用 `story-release` 生成只含标题与正文的发布稿。
5. 用 `story-qc --release` 检查元数据、禁用套话和提前信息。
6. 人工连续阅读，记录仍需复审的语言问题。

## Observed result

在一次三章脱敏复核中，工作稿和发布稿正文保持一致，发布稿没有工作元数据泄漏，未命中预设信息边界和套话规则。工具没有替作者判断文本是否“像真人”，而是把可机械复核的错误先暴露出来，把语言判断留给作者和编辑。

## What this case does not claim

这个案例不证明签约结果，不提供“AI率”，也不代表所有中文小说都应使用同一套规则。它只说明一个可重复的人工审阅加自动报警流程如何落地。
